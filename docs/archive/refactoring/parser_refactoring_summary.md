## 리팩토링 원칙

1. **단일 책임 원칙 (SRP)**: 각 함수는 하나의 작업만 수행
2. **순수 함수 유지**: 상태 없는 함수로 유지 (프로젝트 규칙 준수)
3. **타입 힌트**: 모든 함수에 입력/출력 타입 명시
4. **명확한 네이밍**: 함수명으로 동작 의도 파악 가능
5. **동작 보존**: 기존 테스트를 모두 통과하여 회귀 방지

## 코드 품질 개선 효과

### 가독성
- 함수명만으로 동작 파악 가능
- 중첩 깊이 감소 (최대 3단계 → 최대 2단계)
- 각 함수가 10~20줄 이내로 짧아짐

### 유지보수성
- 버그 발생 시 문제 함수 특정 용이
- 새로운 파싱 로직 추가 시 기존 코드 영향 최소화
- 셀렉터 변경 시 해당 헬퍼 함수만 수정

### 테스트 용이성
- 각 헬퍼 함수를 개별적으로 테스트 가능
- 실패 시 정확한 원인 파악 가능
